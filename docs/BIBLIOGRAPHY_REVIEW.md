# DOIによる書誌情報の確認・更新

## 入口

一覧画面の「メタデータ補完」から「DOIから書誌情報を更新」を開きます。
ログイン中のユーザーの全ライブラリが対象です。

1. DOIだけをCrossrefへ送信する確認欄にチェックし、候補を取得します。
2. 現在値と候補の差分を確認し、更新する文献・項目を選びます。
3. 「変更前バックアップを準備」で現在値を再取得します。
4. JSONをダウンロードして保管し、上書きの確認欄にチェックします。
5. 「バックアップを保存して更新」を押します。

著者・タイトル・雑誌・年・DOI・巻・号・ページまたは論文番号・出版社を更新できます。
取得先に値がない項目は空欄で上書きしません。DOIとタイトルの大きな不一致は更新対象にしません。
Crossrefも完全ではありません。刊行年（オンライン先行公開と冊子）、省略名、数式などは必ず確認してください。

## バックアップと復元

更新前の書誌情報と著者行を、非公開の `paper-pdfs` バケットの
`<user_id>/metadata-backups/<uuid>.json` に保存します。
保存に失敗した場合はDBの更新を開始しません。PDFやメモは書き換えません。

画面の「書誌情報をバックアップから復元」で、保存済みバックアップを読み込むか、
ダウンロードしたJSONをアップロードします。復元前の状態も別のバックアップに保存します。
復元は、このバックアップで更新した書誌項目と著者だけが対象です。
自分以外のアカウントや別文献の著者行を復元先に指定できません。

候補取得後に更新された文献はスキップします。更新は文献単位で進み、バッチ全体を
単一トランザクションにはしていません。書誌項目の更新後に著者更新が失敗すると
「未完了・要確認」と表示されます。結果と変更前バックアップを保持し、その文献を復元してください。
バックアップJSONには書誌情報が含まれます。公開リポジトリへ追加しないでください。

## 管理者による読み取り専用監査

リポジトリ直下を作業ルートにして、リンク済みSupabase CLIで
`scripts/sql/audit_bibliography.sql` を読み取り実行します。
認証情報・メモ・PDFを取得しない書誌情報専用のSELECTです。

スナップショットJSONを `db_backups/` に保存後、外部送信の承認を得てから実行します。

```powershell
python scripts/audit_bibliography.py db_backups/<snapshot>.json
```

Crossrefへ送るのはDOIのみです。結果JSONと差分Markdownを `db_backups/` に生成します。
このスクリプトはDBの更新を行いません。外部RIS等の連番をDB IDとみなさず、DOIで照合してください。
